Choosing options

In this chapter you'll choose what goes in a stream's header, and see how each choice changes the size.

Every EXI stream starts with a short header. At its smallest it is a single byte. It can also carry a $EXI cookie, so tools can spot the format, and an options document that tells the decoder how the body was written.

flowchart LR C["$EXI cookie<br/>(optional, 4 bytes)"] --> H["header bits<br/>(always)"] H --> O["options document<br/>(optional)"] O --> B[body]

If the options are not in the header, both sides must agree on them some other way, such as in a protocol spec or a config file. The EXI spec calls this out of band. Options are keyword arguments to strict_options, and header settings are keyword arguments to HeaderConfig:

# Named, so a decoder can check a stream's schemaId against it.
tables = EXIFormat.with_schema_id(EXIFormat.compile_files(data("order.xsd")), "urn:rexi:interop:order")
xml = read(data("order.xml"), String)

plain = EXIFormat.HeaderConfig()
with_options = EXIFormat.HeaderConfig(; include_options = true)
with_cookie = EXIFormat.HeaderConfig(; cookie = true, include_options = true)
cases = [
    ("bit-packed", EXIFormat.strict_options(), plain),
    # Every event code and value starts on a new byte: bigger, but easier to
    # read in a hex dump.
    ("byte-aligned", EXIFormat.strict_options(; alignment = EXIFormat.ALIGN_BYTE_ALIGNED), plain),
    ("options in header", EXIFormat.strict_options(), with_options),
    ("cookie + options + schemaId", EXIFormat.strict_options(; schema_id = "urn:rexi:interop:order"), with_cookie),
]

streams = map(cases) do (label, options, header)
    exi = EXIFormat.encode_xml(xml, tables; options, header)
    println(rpad(label, 28), " ", lpad(length(exi), 4), " bytes  starts ", hex_start(exi, 8))
    (exi, options, header)
end

# A stream that carries its options can be decoded without being told them. The
# others need them passed in.
decoded = map(streams) do (exi, options, header)
    EXIFormat.decode_to_xml(exi, tables; options = header.include_options ? nothing : options)
end
println("all four decode to the same XML: ", all(==(decoded[1]), decoded))

# Options this library does not support are refused, never guessed at.
for (label, options) in [("compression", EXIFormat.strict_options(; compression = true)),
                         ("non-strict", EXIFormat.ExiOptions())]
    try
        EXIFormat.validate_options(options)
        println(label, ": accepted")
    catch e
        e isa EXIFormat.UnsupportedError || rethrow()
        println(label, ": refused as unsupported")
    end
end

byte-aligned                  145 bytes  starts 80 00 0f 4f 52 44 2d 32
options in header             129 bytes  starts a0 40 f4 f5 24 42 d3 23
cookie + options + schemaId   157 bytes  starts 24 45 58 49 a0 30 61 d5
all four decode to the same XML: true
compression: refused as unsupported

Which should I use?

SettingPick it when
Bit-packed, options out of bandBoth ends are yours. This is the smallest.
Options in the headerReaders should not need to be told the options. For strict options the document is only a few bits, so here the size does not change.
CookiePeople or tools may need to recognize the file. The 24 45 58 49 above is $EXI.
schema_idReaders should be able to check they have the right schema. Name the tables with the same id (with_schema_id), and the decoder refuses a stream that names another schema.
Byte-alignedYou are debugging. Text like 4f 52 44 (ORD) shows up in a hex dump.

EXIFormat refuses options it does not support when you build the encoder, so you find out right away.
