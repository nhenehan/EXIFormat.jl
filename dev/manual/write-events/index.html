Writing events

In this chapter you'll build an EXI document straight from your program's data, with no XML text at all.

The encoder works like the decoder in reverse: you call one function per event.

const NS = "urn:rexi:interop:order"

"""Writes `<name>value</name>` in the order namespace."""
function text_element!(enc, name, value)
    EXIFormat.start_element!(enc, NS, name)
    EXIFormat.characters!(enc, value)
    EXIFormat.end_element!(enc)
end

tables = EXIFormat.compile_files(data("order.xsd"))
enc = EXIFormat.Encoder(tables, EXIFormat.strict_options())

EXIFormat.start_document!(enc)
EXIFormat.start_element!(enc, NS, "Order")
# The schema puts attributes in no namespace, so their URI is "". Strict EXI
# wants attributes sorted by name, which is also the order here.
EXIFormat.attribute!(enc, "", "orderId", "ORD-2026-0007")
# A typed value goes in as it is, with no text to parse.
EXIFormat.attribute!(enc, "", "priority", true)

EXIFormat.start_element!(enc, NS, "Customer")
EXIFormat.attribute!(enc, "", "loyaltyId", "L-8821")
text_element!(enc, "Name", "Raven Bookstore")
text_element!(enc, "Tier", "gold")
EXIFormat.end_element!(enc)

items = [
    ("BK-001", "Distributed Systems Patterns", 2, "42.95"),
    ("BK-014", "Practical EXI", 1, "31.50"),
]
for (sku, description, quantity, price) in items
    EXIFormat.start_element!(enc, NS, "Item")
    EXIFormat.attribute!(enc, "", "sku", sku)
    text_element!(enc, "Description", description)
    text_element!(enc, "Quantity", quantity)
    # `Lexical` is text that the encoder parses with the schema's type, here
    # xs:decimal, just as if it came from an XML file.
    text_element!(enc, "Price", EXIFormat.Lexical(price))
    EXIFormat.end_element!(enc)
end

text_element!(enc, "Notes", "gift-wrap requested")
EXIFormat.end_element!(enc)
EXIFormat.end_document!(enc)
exi = EXIFormat.finish!(enc)

# The same document, encoded from the XML file, gives the same bytes.
from_xml = EXIFormat.encode_xml(read(data("order.xml"), String), tables)
println("EXI: ", length(exi), " bytes")
println("same bytes as encoding order.xml: ", exi == from_xml)
EXI: 129 bytes
same bytes as encoding order.xml: true

The encoder follows the schema

The grammar works like a map of what may come next. After start Order, the encoder expects @orderId, then perhaps @priority, then a Customer, and so on:

stateDiagram-v2 direction LR [*] --> orderId: start Order orderId --> priority orderId --> Customer priority --> Customer Customer --> Item Item --> Item Item --> Notes Item --> [*]: end Order Notes --> [*]: end Order

If you call something out of order, such as Item before Customer, the encoder throws a GrammarError that says what it expected. Two rules trip people up:

  • Attributes come first, sorted by name. Strict EXI wants them in the schema's sorted order, before any child elements.
  • Unqualified attributes have no namespace. This schema puts elements in urn:rexi:interop:order, but attributes use "".

Three ways to pass a value

ValueMeaning
"gold"Text. A string field stores it as it is. Other types parse it, like text from an XML file.
true, 2A typed value, used as it is.
EXIFormat.Lexical("42.95")Text that EXIFormat always parses with the schema's type.

Lexical makes it clear you mean "parse this". Typed values skip the parsing.
