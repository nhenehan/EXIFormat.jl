Schemas and tables

Turn an XML Schema into the grammar tables that every encoder and decoder needs. Compile once and reuse the tables.

EXIFormat.compile_files — Function
compile_files(paths...; load_options = SchemaLoadOptions()) -> GrammarSet

Compiles XSD files (and what they import and include) into grammar tables. Includes and imports may only read files under the main files' folders unless load_options says otherwise (see SchemaLoadOptions).

EXIFormat.compile_string — Function
compile_string(xsd; base_dir = nothing, load_options = SchemaLoadOptions()) -> GrammarSet

Compiles one XSD document given as text; relative schema locations resolve against base_dir. Includes and imports may only read files under base_dir (with no base_dir, none at all) unless load_options says otherwise.

EXIFormat.SchemaLoadOptions — Type
SchemaLoadOptions(; root = nothing, max_file_bytes = 16 * 1024 * 1024, max_grammar_size = 100_000)

Rules for loading a schema: which files xs:include and xs:import may read, how big one schema file may be, and how big one type's content model may grow once group references are replaced and maxOccurs copies are made, counted in grammar rules (nothing: no limit for either size). EXI builds one copy of a particle for each allowed occurrence (https://www.w3.org/TR/exi/#particles), so maxOccurs="4000000000", or groups that each use the one before twice, would otherwise use up memory.

A schema names other schema files with schemaLocation. Without a rule, a hostile schema could name any file the program can read (/etc/passwd, ../../secrets), or one that never ends (/dev/zero) or never answers (a named pipe); the error messages would also tell which files exist. So by default every included or imported file must sit under the main schema's folder. root is:

  • nothing (default): under the folders of the main schema files (for compile_string, under its base_dir; with no base_dir, no file at all);
  • a folder path: under that folder, for sets that reach outside the main schema's folder (UBL's ../common/..., for example);
  • :anywhere: any local file, only for schemas you trust.

In every mode only regular files are read (no pipes or devices), a schemaLocation that is a URL is refused (nothing is fetched over a network), and a file over max_file_bytes is refused, each with a SchemaError that says "refused".

EXIFormat.GrammarSet — Type
GrammarSet

All the grammar tables of one schema. Built at run time by the schema compiler, or written ahead of time as Julia source by SchemaGen.

  • strings: every string the tables name, referred to by StrIdx
  • uris, prefixes, local_names: the initial string table (spec D.3); each UriEntry has spans into prefixes and local_names, which hold StrIdx
  • productions, rules, grammars: the grammars
  • elements, global_elements (sorted by local name, then URI, so their order is the DocContent event-code order), global_attributes, types
  • enum_sets (spans into enum_values, which hold StrIdx)
  • schema_id: the schemaId this schema goes by, if any

EXIFormat.grammar_listing — Function
grammar_listing(g) -> String

A plain listing of the grammar tables: the URIs and names, element and type declarations, and every grammar's rules with their productions in event-code order. It is the same text as rexi dump-grammar, so the two compilers can be compared line by line.
